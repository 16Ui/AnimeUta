# 领域模型 V1

## 目标

本文档用业务视角说明 AnimeUta 第一版核心实体，帮助在进入数据库细节前先建立清晰的领域认知。

## 核心实体

### 1. 歌曲（Song）
歌曲是系统最核心的播放对象。

需要承载的信息包括：
- 多语言标题
- 时长
- 语种
- 音频来源
- 所属作品
- 参与艺人
- 所属专辑

### 2. 艺人（Artist）
艺人是歌曲的参与者。

可能包括：
- 歌手
- 乐队 / 组合
- 声优
- 作曲 / 作词相关主体

### 3. 作品（Work）
作品是歌曲的来源上下文。

可能包括：
- 动画
- 游戏
- 剧场版
- 视觉小说

在 ACG 场景中，很多用户是按作品找歌，而不是按艺人找歌，所以作品是核心实体。

### 4. 专辑（Album）
专辑是歌曲的发行载体。

可能包括：
- 单曲
- 原声带
- 角色歌专辑
- 精选集

### 5. 用户账号（User Account）
承载登录与安全相关信息。

### 6. 用户资料（User Profile）
承载展示与偏好信息，例如昵称、头像、语言偏好。

### 7. 歌单（Playlist）
用户组织歌曲的集合。

### 8. 收藏（Favorite）
第一版只覆盖“用户收藏歌曲”。

### 9. 播放历史（Play History）
记录用户播放过哪些歌曲以及最近播放时间。

## 核心关系

### 歌曲 与 艺人
- 多对多
- 一首歌可以有多个艺人
- 一个艺人可以参与多首歌
- 关系还需要表达角色，例如主唱、作曲、作词

### 歌曲 与 作品
- 多对多
- 一首歌可以关联一个或多个作品
- 同时还要表达关系类型，例如 OP、ED、插曲、角色歌

### 歌曲 与 专辑
- 多对多
- 一首歌可能出现在多个专辑版本中
- 专辑中还需要记录碟号、曲序

### 用户 与 歌单
- 一对多
- 一个用户可以创建多个歌单

### 歌单 与 歌曲
- 多对多
- 还需要记录歌曲在歌单中的位置

### 用户 与 收藏歌曲
- 多对多
- 第一版只做歌曲收藏

## 多语言策略

第一版采用直列字段方案：
- 标题类字段直接放在主表中
- 例如 `title_ja`、`title_zh`、`title_en`、`title_romaji`

原因：
- 三语范围明确
- 查询简单
- 更适合 MVP
- 实现成本低于通用翻译表

## 搜索支撑对象

为保证搜索体验，需要为以下实体准备 alias：
- 歌曲
- 艺人
- 作品

这些 alias 用于承载：
- 别名
- 简称
- 译名补充
- 罗马音补充

## 当前阶段明确不引入的领域

- 评论
- 乐评
- 社区互动
- 下载离线
- 推荐系统
- 通用翻译中台
- 通用搜索投影表
