# 模块边界

## 前端

- `api`：HTTP 请求与类型适配，不保存业务状态。
- `store`：登录态和全局播放器状态。
- `pages`：路由级工作流，包括导入、详情、学习和管理。
- `components/music`：歌曲列表、歌词和管理编辑器。
- `components/study`：歌曲分词选择与学习卡片。
- `i18n`：所有用户可见文案的中日英资源。

## 后端单体

- `auth`：邀请制账号、角色、会话、刷新与撤销。
- `songs`：歌曲导入、音频标签、歌词版本、审核和 ACG 元数据。
- `media` / `bundle`：私有音频、签名播放、Range、图片和安全 ZIP 导入。
- `lyrics`：LRC、SRT、TXT 解析。
- `lyric-jobs` / `llm`：持久任务、OpenAI-compatible 调用、失败重试。
- `study`：分词、词元、词库、双向卡片和间隔复习。
- `library`：收藏、歌单、播放历史和行为事件。
- `discovery`：搜索、建议、热词、榜单和轻量召回。
- `acg`：创作者、角色、声优、发行商、厂牌与版本组的资料、别名、关联和权限过滤。

SQLite 是唯一真实数据源。任务状态也写入 SQLite，因此服务重启后可以继续处理。音频不进入数据库，数据库只保存受控相对路径。

## 权限

- `owner`：用户与邀请、角色、全部管理能力。
- `admin`：歌曲、歌词、审核和元数据管理。
- `user`：自己的私人曲库、学习数据和共享申请。

公开在产品文案中统一称“共享曲库”，不是互联网公开发布。
## 日语学习分析

`backend/src/japanese-study.ts` 是歌词学习分析边界：Kuromoji 负责分词和基本形，WanaKana 负责平假名与罗马音转换，Tomoshi SQLite 以只读连接提供候选词条。只有无候选或无法唯一确定义项的 token 会发送给外部 LLM，LLM 不负责重新切分整段歌词。
