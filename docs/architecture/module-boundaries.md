# 模块边界说明

## 文档目的

本文档用于约束 AnimeUta 第一阶段各模块职责，避免后续实现时边界混乱。

## 前端模块边界

### 前端负责
- 页面展示与交互
- 路由跳转
- 全局播放器状态
- 登录态在前端的展示与消费
- 三语界面文案切换
- 调用后端 API 获取数据

### 前端不负责
- 核心业务真相维护
- 权限规则裁定
- 搜索排序规则定义
- 收藏、歌单、用户数据的最终一致性

## 后端模块边界

### 后端负责
- 用户认证与鉴权
- 歌曲、艺人、作品、专辑的数据组织
- 收藏、歌单、播放历史等业务规则
- 搜索召回与排序逻辑
- 数据校验、约束、持久化

### 后端不负责
- 页面布局与展示细节
- 前端本地 UI 状态
- 纯视觉交互逻辑

## 模块职责划分

### `auth`
- 登录注册
- 密码校验
- Token / 会话相关逻辑
- 账号状态管理

### `user`
- 用户资料
- 语言偏好
- 头像、昵称等展示信息

### `music`
- 歌曲、艺人、专辑核心数据
- 歌曲详情聚合

### `work`
- 动画 / 游戏作品信息
- 歌曲与作品的关联

### `playlist`
- 歌单创建、修改、删除
- 歌单歌曲排序

### `favorite`
- 用户收藏歌曲

### `search`
- 多语言搜索
- 别名召回
- 搜索结果排序

### `agent`
- 当前阶段只保留入口边界
- 后续对接独立 `agent-service/`

## 关键边界原则

1. 前端只消费 API，不直接绕过后端访问数据库
2. 搜索规则统一放在后端，不在前端自行拼业务逻辑
3. 播放器状态属于前端全局状态，但播放历史落库属于后端职责
4. 多语言 UI 文案在前端处理，多语言内容字段在数据库与后端响应层处理
5. Agent 能力与 Java 主服务解耦，避免一开始把 AI 逻辑硬塞进主后端
