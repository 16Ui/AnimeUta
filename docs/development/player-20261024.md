# Player update 2026-10-24

## Behavior

- Selecting a song anywhere appends it to the existing queue if absent and selects it. Existing entries retain their position. Invalid or unavailable selections do not clear the queue. Next/previous and remove actions remain available.
- Volume maps normalized slider values to squared media gain: 5% becomes 0.0025, with mute and maximum preserved.
- `/api/v1/users/me/lyric-preferences` stores validated partial updates in the user's database row. Shared fields: fontSize (18-48), showFurigana, showRomaji, showNextLine. Timing remains on the existing lyric/song resource, not in user preferences.
- Same-origin windows invalidate preferences through storage events; other devices refresh every 15 seconds and on focus. Failed saves show an error instead of reporting success.
- Desktop lock is device-local. As of 0.1.3, controls stay mounted at a fixed top-right position and appear only on hover. Locked lyrics pass clicks through, but the toolbar remains clickable for unlocking. The main player's lock button is a fallback. Window height follows display preferences rather than sentence dimensions. Chinese translation uses a sans-serif medium weight and restrained shadow.
- Details/content/AI share a compact cover header and navigation, with neutral surfaces and responsive action rows.
