# AnimeUta 产品需求基线 V1

## 1. 产品定位

AnimeUta 是一款面向个人和不超过约 10 名受邀好友的 ACG 日语歌曲学习应用。它不是公共音乐平台，也不追求海量曲库；核心价值是把用户合法持有的少量歌曲整理为可播放、可理解、可逐词记忆的长期学习材料。

产品主闭环：

1. 从电脑或手机一次性导入音频、歌词与封面。
2. 自动识别标签和内嵌素材，用户预览并修正。
3. 播放歌曲并查看同步的日文、中文、注音和学习解释。
4. 从歌词中选取部分或全部词语加入个人词库。
5. 通过双向回忆、揭晓、朗读和间隔复习完成记忆。
6. 从学习卡回到原歌曲、原句和时间位置复习语境。

## 2. 用户与内容边界

### P0 账号与权限

- 空系统的第一个注册账号成为 `owner`，不提供默认演示账号。
- 后续账号必须使用邀请码注册。
- 支持登录、刷新会话、退出、修改资料、上传头像和修改密码。
- `owner` 管理邀请、账号状态与角色；`admin` 管理内容；`user` 使用私人曲库和申请共享。
- 收藏、歌单、播放历史、词库、学习卡和复习记录必须按用户隔离；歌单不提供公共可见模式。

### P0 私人与共享

- 普通用户导入的歌曲默认只进入私人曲库。
- 普通用户可主动申请将歌曲加入共享曲库；是否需要审核由部署配置决定。
- 私人歌词、AI 歌词草稿和私人批注不因 `pending` 状态自动进入管理后台；只有用户明确提交审核后管理员才可查看和处理。
- 所有者和管理员可以直接维护共享曲库。
- “共享”只表示受邀用户可见，不表示向互联网发布。

## 3. 智能导入

### P0 文件入口

- 支持从桌面和移动端文件选择器导入音频。
- 支持同时选择歌词和封面，也支持包含这些文件的 ZIP。
- 支持 MP3、FLAC、M4A/MP4、WAV、OGG/Opus、AAC 音频，以及 LRC、SRT、TXT 歌词。
- ZIP 必须限制条目数、解压体积和文件类型，并拒绝加密包与路径穿越。

### P0 移动端导入体验

- Android/iOS 必须调用系统文件选择器，兼容“文件”、网盘和其他系统文档提供方，不要求用户先把文件复制到应用目录。
- 移动端允许只选择一份音频完成导入；同名歌词和封面可在预览页继续补选。
- 同时准备好音频、歌词和封面时，推荐用多文件选择或 ZIP 一次导入，减少手机上的重复操作。
- 导入完成后文件保存在服务端，其他设备只需登录并在线播放，不能要求每台手机重复导入。
- 从其他应用通过系统“分享至 AnimeUta”直接导入属于增强能力，不阻塞 V1 发布。

### P0 自动识别与确认

- 优先读取标题、艺人、专辑、年份、时长、内嵌封面和内嵌歌词。
- 标签不足时从文件名推断标题和艺人。
- 提交前展示导入预览，允许修正标题、语言、作品、专辑、封面等信息。
- 用户确认后才创建正式歌曲；放弃或过期的预览必须清理临时文件。
- 没有歌词时允许先导入音频，再创建 AI 转写任务或由管理员补录。

## 4. 曲库与 ACG 元数据

### P0 基础曲库

- 首页、搜索、收藏、歌单和历史都以封面、标题、艺人、时长及友好时间展示歌曲。
- 支持歌曲详情、收藏、播放历史、歌单增删与排序。
- 管理员可编辑、审核和删除歌曲，删除后相关媒体与关系数据不得残留为可访问内容。

### P1 ACG 领域信息

- 支持艺人、作品、专辑、角色、声优、发行商、厂牌和创作者。
- 创作者要区分作词、作曲、编曲等职责。
- 支持 TV Size、Full、Instrumental、Cover、Live、OST 变奏等版本类型。
- 同曲不同版本通过版本组聚合，而不是作为无关搜索结果散落展示。
- 所有主要实体支持图片、别名和详情页。

### P1 曲库搜索

- 搜索歌曲、艺人、作品和专辑，并支持中文、日文、罗马音及别名召回。
- 搜索框输入时显示当前学习曲库中的分类建议。
- 点击建议进入对应歌曲、艺人、作品或专辑详情。

## 5. 播放器与歌词体验

### P0 播放器

- 支持播放/暂停、可拖动进度、上一首/下一首、播放队列、单曲循环、列表循环和顺序播放。
- 显示真实时长与当前时间，记住用户上次音量。
- 点击全局播放器中的歌曲信息可以回到歌曲详情和歌词位置。
- 浏览器或移动系统支持时，接入后台播放、锁屏信息、耳机控制与 Media Session。
- 音频与图片使用短期签名地址，音频支持 HTTP Range；私有媒体目录不可直接公开。

### P0 歌词展示

- 支持 LRC、SRT、TXT 和音频内嵌歌词。
- 每句可包含日文原文、中文翻译、汉字上方的假名、罗马音和起止时间。
- 当前句随播放进度高亮，歌词容器内部自动滚动，不能改变整个页面的滚动位置。
- 用户主动滚动后短暂停止跟随，再恢复自动定位。
- Windows 桌面客户端支持独立置顶桌面歌词窗口，显示当前句原文、翻译、罗马音和下一句；窗口可拖动、隐藏，不占用主播放页面空间。
- 作词、作曲、编曲等歌曲信息与歌词正文分区展示并适配窄屏。
- 支持当前歌词逐句编辑，学习批注默认作为个人笔记保存。
- 私人学习场景不设置歌词投稿、批准或驳回流程。

## 6. AI 歌词处理

### P0 任务能力

- 支持 `transcribe`、`translate`、`furigana`、`align`、`annotate` 和 `tokenize`。
- 任务必须持久化状态、输入、输出、错误和重试次数，服务重启后可以继续处理。
- 前端展示等待、处理中、成功和失败，并提供明确失败原因与重试入口。
- 完成后自动刷新歌词或词语结果。

### P0 质量与限制

- AI 接口采用可配置的外部 OpenAI-compatible provider，文本处理与语音转写均不依赖本地模型运行时。
- 结构化任务必须校验返回格式；无效结果应失败，不能伪装成功或写入模拟内容。
- 转写尽可能保存逐句与逐词时间；缺少逐词时间时可以在句内估算，但要保留来源差异。
- 普通用户受每日调用额度约束；所有调用需鉴权并记录。
- 普通用户可以处理自己可见的共享歌曲，但任务记录和生成内容必须按请求者隔离，并写入该用户的私人歌词草稿；不同用户的个人任务不得互相阻塞。
- 用户可检查和修改 AI 结果，AI 不拥有最终内容决定权。

## 7. 日语学习板块

### P0 从歌词选词

- 对歌曲歌词分词，识别表层词、基本形、平假名、片假名、罗马音、词性、中文释义和双语例句。
- 同一基本形去重，但保留它在不同歌曲、歌词句和时间位置中的出现记录。
- 用户可以选择部分词语、全选或取消选择，并加入一个或多个个人词库。
- 分词结果允许管理员或用户修正，不能完全依赖 LLM。

### P0 背诵流程

- 支持日文到中文、中文到日文两种方向。
- 卡片初始只显示题面，用户先在脑中回忆，再点击揭晓。
- 揭晓后显示中文释义、平假名、片假名、罗马音、词性、日文例句、例句翻译、来源歌词和学习批注，并可触发日语朗读。
- 用户以忘记、困难、良好、简单四档评分。
- 调度器根据评分安排下一次复习，形成类似墨墨背单词体验的间隔重复，而不复制其专有实现。
- 可设置每日新词数、每日复习上限、默认方向和揭晓后自动朗读。

### P0 上下文学习

- 学习卡必须保留来源歌曲、歌词句和尽可能精确的时间位置。
- 用户可从卡片一键跳转歌曲，在对应位置播放并查看整句。
- 歌词学习批注支持词汇、语法、文化背景和翻译解释。
- 今日学习页面进入后直接开始背词；统计、词库、复习历史和设置通过工具按钮按需打开。

### P1 学习管理

- 支持词库重命名、删除和排序。
- 支持学习卡暂停、移除、转移词库及手动修正释义。
- 支持复习历史与趋势图，并在真实使用数据基础上校准调度参数。

## 8. 管理后台

### P0 内容管理

- 导航使用“管理歌曲”“用户与邀请”等明确名称，不向用户暴露“元数据”等内部术语。
- 歌曲管理先展示封面与标题列表，点击后进入详情编辑。
- 支持编辑歌曲、图片、作品、角色、声优、创作者职责、版本类型和版本组。
- 不提供独立歌曲或歌词审核模块，管理员直接维护歌曲资料。

### P0 用户管理

- 所有者可创建和撤销邀请码、查看用户、禁用账号并调整 `admin/user` 角色。
- 管理操作必须经过后端权限检查，不能仅靠前端隐藏按钮。

## 9. 多端与国际化

### P0 多端

- React 前端同时服务桌面 Web、Tauri Windows 客户端和 Capacitor Android/iOS。
- 页面在桌面与手机宽度下均可用，文字、按钮、播放器和歌词不能重叠或溢出。
- 用户只需把文件导入服务端一次，登录自己的其他设备即可访问，不要求每台设备重复上传。
- Android/iOS 的后端地址可在构建时设置，也可在登录页测试并保存；真机不得依赖设备自身的 `localhost`。
- 移动端必须正确处理安全区、虚拟键盘、返回手势和底部播放器，导入、播放、歌词与复习主流程不能依赖鼠标悬停。

### P0 国际化

- 所有用户可见的导航、状态、错误、时间、语言名称和枚举值使用 i18n。
- 支持简体中文、日文和英文；例如语言显示为“日语/日本語/Japanese”，不直接暴露 `ja`。
- `local_upload`、`oss_upload` 等内部值不得直接显示给用户。

## 10. 技术与运维约束

### 当前基线

- 前端：React + TypeScript，共享 Web、Tauri 与 Capacitor UI。
- 后端：TypeScript + Fastify 单体服务。
- 数据：SQLite WAL 是唯一权威数据库，使用顺序迁移。
- 任务：SQLite 任务表 + 同进程持久 Worker。
- 媒体：默认保存在服务端私有目录；数据库只保存受控相对路径。
- 部署：单机 Node.js 服务即可运行，不依赖 Docker。

### 非功能要求

- 目标规模为约 10 个账号，优先低资源占用、低运维成本、可恢复性和数据可携带性。
- 服务重启不能丢失账号、内容、任务或学习进度。
- SQLite 数据库、媒体目录和配置需要可一并备份与恢复。
- API 必须鉴权、校验输入并限制上传体积；密码安全哈希，会话可刷新和撤销。
- Redis、Kafka、PostgreSQL、分布式锁和微服务只有在真实瓶颈出现后才重新评估。

## 11. 后续增强

- 更可靠的本地日语形态分析器与离线词典。
- 阿里云 OSS 私有桶适配及临时签名地址。
- Android/iOS 系统分享目标，让系统文件管理器或其他应用把文件直接发送到 AnimeUta。
- 跟唱、录音对比、发音反馈和逐句跟读。
- 基于个人学习记录的选词建议，不建设歌曲推荐系统。

## 12. 明确不做

- 不抓取网易云等平台的未授权音频或调用私有接口。
- 不建设海量公共曲库，也不把用户文件默认公开。
- 不做弹幕、陌生人社交、附近的人、秒杀、交易或复杂 Feed。
- 不为了展示技术而引入 Redis、Kafka、PostgreSQL、分布式锁或微服务。
- 不照搬网易云音乐、Spotify、Apple Music 或墨墨背单词的界面与专有实现，只吸收适合本产品的交互原则。

## 13. V1 验收主路径

1. 新部署中创建首位所有者并生成邀请码，好友完成注册和登录。
2. 在桌面或手机选择一首带标签的音频，系统读出标题、艺人、专辑、时长和封面；用户修正后完成导入。
3. 播放歌曲并拖动进度，刷新后音量保持；队列、循环、后台控制可正常使用。
4. 上传 LRC/SRT/TXT 或创建转写任务，歌词按时间高亮并在容器内滚动。
5. 创建翻译、假名、对轴、批注和分词任务；成功写回，非法输出显示失败且可重试。
6. 从歌曲中选择词语加入词库，完成两种方向的揭晓、朗读和四档评分。
7. 从下一张到期卡片进入复习，并能跳回原歌曲的原句时间。
8. 普通用户申请共享，管理员在独立后台审核并补充 ACG 元数据。
9. 同一账号在另一设备登录后可看到曲库与学习进度，私人数据不会串到其他账号。
10. 备份并恢复数据库与媒体目录后，歌曲、歌词、账号和复习状态保持完整。
