# AnimeUta V1 需求总览与验收矩阵

## 1. 一句话定义

AnimeUta 是一个服务个人和不超过约 10 名受邀好友的 ACG 日语歌曲学习应用。用户只需把自己持有的音频、歌词和封面导入服务端一次，之后即可在电脑或手机上播放、理解歌词、选词并进行间隔复习。

它不是公共音乐平台、资源抓取工具或高并发互联网服务。V1 的重点是把“导入一首歌 -> 听懂歌词 -> 选词 -> 持续复习”做完整。

## 2. 用户与内容边界

| 角色 | 能力 |
| --- | --- |
| Owner | 首位注册者；管理邀请、用户状态、管理员角色和全部共享内容 |
| Admin | 审核歌曲、歌词和学习批注，维护 ACG 元数据 |
| User | 管理私人曲库、申请共享、播放歌曲并使用个人学习数据 |

内容默认规则：

- 普通用户导入的歌曲、歌词草稿和批注默认私有。
- 只有主动提交并审核通过的内容才进入受邀用户可见的共享曲库。
- 收藏、歌单、历史、词库、学习卡和复习记录始终按用户隔离。
- “共享”只面向当前私有部署中的受邀账号，不代表互联网公开。

## 3. V1 用户主流程

1. 首位用户注册为 Owner，并邀请少量好友加入。
2. 用户从桌面或手机选择音频，也可同时选择歌词、封面或 ZIP。
3. 系统读取音频标签、内嵌封面、内嵌歌词和文件名，生成可修改的导入预览。
4. 用户确认后，歌曲进入私人曲库；需要时提交共享审核。
5. 用户播放歌曲，查看随进度高亮的日文、中文、假名与罗马音歌词。
6. 缺失或不完整的歌词可交给 AI 转写、翻译、注音、对轴、批注和分词。
7. 用户从歌词中选择部分或全部词语，加入一个或多个个人词库。
8. 用户按日文到中文或中文到日文方向进行揭晓式复习，并用四档评分安排下次复习。
9. 用户可从学习卡跳回原歌曲、原歌词句和相应播放时间。

## 5. 领域能力边界

### 音乐部分

- `Song` 表示一个可独立播放和学习的具体音频版本。
- `Song Version Group` 聚合同曲的 Full、TV Size、Instrumental、Cover、Live 和 OST 变奏。
- 歌曲、艺人、作品、专辑、角色、声优、发行商、厂牌、创作者和版本组都可搜索并进入独立详情。
- ACG 实体支持多语言名称、别名、图片、关系歌曲和管理员编辑；歌曲可通过创作者职责和版本组表达领域关系。

### 歌词与学习部分

- `Lyric Version` 是可独立审核和修改的一份歌词。
- `Lyric Line` 是同步展示、批注和上下文回跳的最小单位。
- `Lexeme` 是去除不同词形后的学习对象；同一词元可以保留多处歌词出现记录。
- `Study Card` 是“词元 + 词库 + 背诵方向”的个人复习状态，不与其他用户共享。
- AI 只生成草稿或结构化建议，管理员和用户保留最终修改权。普通用户处理共享歌曲时使用自己的私人歌词草稿，任务列表和重试权限也按请求者隔离。

## 6. 技术基线

| 层级 | 决策 |
| --- | --- |
| 前端 | React + TypeScript；同一套 UI 服务 Web、Tauri 和 Capacitor |
| 后端 | TypeScript + Fastify 单体服务 |
| 数据库 | SQLite WAL，唯一权威数据源，顺序迁移 |
| 后台任务 | SQLite 任务表 + 同进程持久 Worker |
| 媒体 | 服务端私有目录；音频与图片使用短期签名地址，音频支持 HTTP Range |
| AI | 外部 OpenAI-compatible provider，文本与转写服务独立可配置 |
| 部署 | 一台运行 Node.js 的设备即可，不依赖 Docker |

这套架构针对不超过约 10 个账号设计。Redis、Kafka、PostgreSQL、分布式锁、微服务和对象存储都不是运行前提，只有出现真实瓶颈或部署需求后才重新评估。

## 7. 明确不做

- 不抓取网易云等平台的未授权音频，不调用其私有接口。
- 不建设海量公共曲库，不做通用音乐平台。
- 不做弹幕、陌生人社交、附近的人、秒杀、交易或复杂 Feed。
- 不要求用户在每台设备重复导入；音频只需导入服务端一次。
- 不照搬网易云音乐、Spotify、Apple Music 或墨墨背单词的界面和专有算法。
- 不为了技术展示引入 Redis、Kafka、PostgreSQL、分布式锁或微服务。

## 8. V1 发布门槛

以下条件全部通过，V1 才算完成：

1. 两个不同账号不能通过搜索、详情 ID、歌词、媒体地址或学习接口看到彼此的私人数据。
2. 至少用 MP3、FLAC、M4A 和 ZIP 各完成一次真实导入，元数据预览可修正。
3. 播放进度、队列、循环、音量记忆和歌词跟随在桌面与手机宽度下正常。
4. 六类 AI 任务至少各有成功或可解释失败，重启后任务状态不丢失。
5. 从真实歌词分词、选词、加入词库、双向复习、评分到来源回跳完整跑通。
6. Owner、Admin、User 三种权限及歌曲/歌词/批注审核流程通过双账号验收。
7. 中文、日文、英文页面不显示裸枚举、内部来源名或未翻译错误。
8. Android 完成一次真机安装和播放验证；iOS 保留明确的待验证记录。
9. 完整备份后在空数据目录恢复，账号、歌曲、歌词、媒体和学习记录一致。
10. 自动化测试、TypeScript 检查、前后端构建、Windows 客户端和 Android 构建全部通过。
