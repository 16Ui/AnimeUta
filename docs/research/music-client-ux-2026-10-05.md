# AnimeUta 音乐客户端体验调研

调研时间：2026-10-05 10:56（Asia/Shanghai，UTC+08:00）。对象：Spotify、Apple Music、网易云音乐的桌面及移动体验。

## 结论与边界

**设计推断：借鉴稳定分区与操作语义，不复制商业音乐平台的首页。** AnimeUta 应围绕“私人曲库找歌 → 持续播放 → 阅读日文歌词 → 查看词义”组织体验；桌面保留紧凑导航、歌曲列表和持续播放条，手机采用底部导航、迷你播放器、独立完整播放页。歌词是学习内容，不是装饰背景。

- **证据**：下文带官方链接的事实，来自本次网页检索、官方帮助、开发者商店说明或公司公告；不等于当前安装版本的实测结果。
- **推断**：优先级、布局尺寸、状态管理与验收条件是针对 AnimeUta 的设计建议，不声称竞品已经这样实现。
- **范围**：React + Tauri 桌面、Capacitor Android；只改进播放、曲库、歌词及现有学习入口。不新增推荐、榜单、社交、评论、审核或新的复习功能；不引入竞品音源、私有接口或歌词抓取。
- **仓库基线**：已读 `CLAUDE.md`、`CONTEXT.md`、`docs/design/ui-layout-reference.md` 与 `frontend/package.json`。旧文档中的发现、榜单、管理界面不构成本次新增需求；Tauri 以本次任务及现有依赖为准。未修改这些文件或前端代码。

## 优先改动与验收

以下均为**设计推断**，供主任务按现状取舍；P0 优先于视觉润色。现有能力只整理体验，不重复建设。

| 优先级 | 改动 | 最小验收条件 |
| --- | --- | --- |
| P0-1 | **播放状态独立于页面。** 曲库、歌单、完整播放页共享一个播放源与队列；完整页打开/关闭只是展示变化。 | 播放中切页、展开歌词、关闭弹层不重播、不出现双音轨；迷你条、完整页和歌曲行的播放状态一致。 |
| P0-2 | **手机底部区域统一计算。** 有当前歌曲才显示迷你条；底部导航、播放器、安全区各占一次高度。完整播放页替代迷你条，不叠两套控制。 | 未选歌曲没有空白播放器占位；360×800、412×915、横屏及键盘弹出时，最后一行内容和播放按钮都可到达。 |
| P0-3 | **歌词滚动与选词解耦。** 歌词容器独立滚动；手动浏览、选择词语时暂停自动跟随，提供“回到当前句”。行旁播放按钮负责跳转，词语点击只查词。 | 查词不跳歌、不被自动滚动拉走；无时间戳不显示可跳转假象；关闭词义面板后仍在原句。不要让点行跳转与词语按钮产生嵌套按钮。 |
| P0-4 | **控制项可用键盘、触摸和读屏完成。** 使用语义按钮与进度滑块，图标有名称，切换项有状态，焦点可见，弹层关闭后返回触发点。 | 不用鼠标也能播放、调进度、开关歌词和关闭队列；输入框及日文组字时不触发播放快捷键；读屏不逐秒播报进度或每句抢读歌词。 |
| P1-5 | **曲库采用统一歌曲行。** 小封面、歌名、演唱者为一级信息；作品/版本、时长按宽度渐进展示。搜索、排序放在列表上方，收藏与更多操作保持固定位置。 | 中日英长标题不挤掉操作；当前播放和仅选中有不同标识；切页回来保留查询与位置；收藏不隐式加入队列。 |
| P1-6 | **队列语义明确。** 桌面抽屉、手机底部面板共用行为；区分立即播放、下一首、加入队尾、从队列移除。 | 移除队列项不删除音频、不改永久歌单；重排不打断当前歌；除拖动外可通过菜单上移/下移；替换手动队列有明确提示或撤销。 |
| P1-7 | **歌词状态和排版完整。** 区分加载、同步歌词、纯文本、暂无歌词、加载失败；原文主导，译文/假名/罗马音独立开关并记住偏好。 | 缺译文不掩盖原文；失败可重试且音频可继续；ruby 上下留白充足、长句自然换行；放大文字后不裁切读音。 |
| P1-8 | **播放反馈反映真实媒体状态。** 区分等待加载、播放、暂停、缓冲、失败；拖动进度时显示预览，完成后再与媒体时间校准。 | 快速切歌不会被旧请求覆盖封面或歌词；签名过期、网络中断时有可重试错误，不显示虚假播放；未知时长不会出现 NaN 或无穷进度。 |
| P2-9 | **保持学习层轻量。** 桌面在歌词旁按需打开词义面板，手机用可关闭的词义面板；详细元数据和已有歌词处理入口留在更多菜单。 | 主播放界面只保留高频控制；词义面板打开时仍能暂停，返回时保留歌曲、时间、歌词位置；不新增复习流程或后台管理模块。 |

无障碍验收基线来自 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)：普通文字对比度至少 4.5:1，关键控件视觉信息至少 3:1；支持键盘、可见且不被遮挡的焦点、非拖动替代操作和文字放大。WCAG AA 的指针目标最低要求是带例外的 24×24 CSS px，不是 44 px。**项目推断**：沿用现有文档的移动主控至少 44×44 CSS px，并在 Android 真机检查实际触摸尺寸；不要把 CSS px、物理像素与 dp 当成同一单位。减少动态效果时取消歌词弹跳与封面运动，不取消当前句标识。

## 跨平台陷阱

| 风险 | 官方依据 | 实施约束/待验证项（推断） |
| --- | --- | --- |
| 浏览器通过不代表 Tauri 通过 | Tauri Windows 使用 WebView2，其他桌面系统使用不同 WebKit 实现。[Tauri WebView](https://v2.tauri.app/reference/webview-versions/) | 分别检查 WebView2 字体、ruby、滚动、焦点与缩放；桌面媒体键、窗口关闭和最小化语义不能靠网页截图证明。不要用 Tauri Android 文档替代本项目 Capacitor Android 的证据。 |
| Android 安全区与键盘重叠 | Android 15 及以上、目标 SDK 35 及以上会启用 edge-to-edge，必须处理系统栏遮挡。[Android 布局说明](https://developer.android.com/develop/ui/views/layout/edge-to-edge) | 核对实际 target SDK、WebView 与原生容器 inset；原生已留边时不可再重复加 CSS 安全区。测试手势导航、三键导航和输入法，不仅测试网页窄屏。 |
| 返回键直接退应用/丢面板 | Capacitor 监听 `backButton` 会禁用默认返回行为。[Capacitor App API](https://capacitorjs.com/docs/apis/app#addlistenerbackbutton) | 返回优先关闭最上层菜单/词义/队列，再收起完整播放器，再回上一页；根页退出行为单独约定。避免多个组件重复注册监听器。 |
| 后台播放不等于保持网页定时器 | Android 官方后台媒体方案采用 `MediaSessionService`，系统通知与媒体会话状态关联。[Media3 后台播放](https://developer.android.com/media/media3/session/background-playback) | 不假设 Capacitor 包装 HTML audio 就自动具备稳定后台播放、锁屏控制、耳机控制。先审查已有原生能力，再做熄屏、切后台、音频焦点和恢复测试；回前台从真实媒体时间重算歌词。 |
| 页面布局与操作状态混用 | Spotify 官方区分曲库与队列；Apple 明确区分下一首与队尾，见上文官方帮助。 | 浏览结果排序不应悄悄重排正在播放的队列；持久歌单、当前队列、当前歌曲、学习选词分别维护状态。 |
| 竞品覆盖率外推 | Spotify、Apple 均说明歌词存在曲目/设备/地区限制；网易公开材料未提供完整操作矩阵。 | 不把 iPhone 翻译、桌面快捷键或官方概念图外推为 Android 功能；不要为对齐竞品而自动下载、缓存私人音频。 |
